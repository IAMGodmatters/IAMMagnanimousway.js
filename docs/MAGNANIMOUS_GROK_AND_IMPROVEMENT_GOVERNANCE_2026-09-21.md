# Magnanimous Grok + Improvement Governance Absorption — 2026-09-21

## Purpose

Magnanimous AI remains the brain, identity, memory owner, reasoning layer, policy layer, orchestrator, verifier and learning system.

This change absorbs useful **public Grok/xAI capability patterns** and useful **general engineering/governance patterns** from the owner-provided private project document without making xAI, Grok, or the source project a dependency.

Nothing in this work copies proprietary provider source code, hidden prompts, model weights, credentials, private backend implementation, restricted datasets or domain-specific racing/wagering logic.

## Optional xAI compute adapter

Agent Mesh now recognizes xAI Grok as an optional metered model-compute adapter when `XAI_API_KEY` is explicitly configured.

Rules:

- priority remains behind the existing free-first provider chain;
- default model is `grok-4.6`;
- API base is `https://api.x.ai/v1`;
- no xAI key is required for Magnanimous to function;
- xAI does not own Magnanimous memory, tools, permissions, routing or orchestration;
- Grok server-side tools are not required because equivalent capability classes are routed through Magnanimous-owned tools first.

## Reusable governance patterns absorbed from the private project document

Only generalizable platform-engineering patterns were retained:

- preserve the current authoritative baseline; never reset newer working code to a stale artifact;
- use explicit precedence when sources or requirements conflict;
- record exact release identity across commit/tree/schema/model/data/config/dependencies/assets;
- maintain one canonical control source plus explicit supersession edges;
- separate source rights for acquisition, retention, training and external processing;
- trace a capability from available/captured through actual consumer use, verification and publication;
- record absent, unsupported, restricted, invalid, unmapped, unused and rejected states instead of hiding them;
- use bounded workers, one writer per shared source, one final integrator and independent review;
- use an evidence-driven repair loop;
- do not treat a helper test as whole-system acceptance;
- distinguish observed, candidate, tested, reviewed, deployed and canary-verified states;
- require real positive cases for promised features;
- preserve failed experiments and unsupported states;
- never claim actions, deployments or tests occurred without evidence.

Horse racing, wagering, track analysis, race prediction, proprietary formulas, simulator rules and other domain-specific material were intentionally excluded.
